## 2. 速度总表（板端实测，单位 ms）

### 2.1 分段

| 配置 | 前处理 | 检测 | NMS | 视觉塔 | LLM | 串行 | **关键路径** | FPS |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| **部署 v3（YOLOE-NPU + L 塔）** | 39.4 | **51.7**（NPU） | 0.4 | 89.4（CLIP-L 28.1 + CN-L 61.3，CUDA Graph） | **78.5**（vLLM） | 259.4 | **207.3** | **4.8** |
| v1（DINO + ViT-B + CN-B） | 39.0 | 92.6（DINO）+ 6.1（ViT-B） | — | 78.7（CN-B @ NPU，含 RoI+投影） | 78.5（与 v3 对齐，同一 Qwen/vLLM 口径） | — | **216.2** | 4.6 |
| GD graft448 + L 塔 | 42.6 | 92.6（GPU） | 0.3 | 89.4 | 78.5 | 303.4 | **303.4** | 3.3 |
| stock HF GD-tiny + L 塔 | 68.7 | 439.9（GPU） | 0.3 | 89.4 | 78.5 | 676.8 | **676.8** | 1.5 |
| YOLOE 原生 PyTorch + L 塔 | 39.1 | 138.4（GPU） | 0.3 | 89.4 | 78.5 | 345.7 | **345.7** | 2.9 |

> **LLM 段统一用 78.5 ms**（Qwen2.5-3B + vLLM + CUDA Graph，629→3 token）。v1 原始管线实测是 198.8 ms，但那走的是 vLLM 的 `prompt_embeds` 路径且 `max_tokens=8`，与 v3 的 token 路径不可比；对齐后所有配置用同一 LLM 口径。

关键路径的计算方式：

- 部署：`39.4 + max(51.7 NPU, 89.4 GPU 塔) + 78.5`
- v1：`39.0 + max(92.6 + 6.1 GPU, 78.7 NPU) + 198.8`
- GD/native/stock：检测器也在 GPU，与塔无法重叠 → 前处理 + 检测 + 塔 + LLM

## 3. 一句话结论

- **精度**：部署模型 F1@0.5 **0.7468**（域平均 0.7462），与 GD 持平，高于 v1 10.1 点；严格 IoU 0.5350 低于 v1 10.9 点（INT8 候选框偏松）。
- **速度**：端到端 **207.3 ms / 4.8 FPS**，比 GD 快 1.46×；与 v1（216.2 ms，同一 LLM 口径）**基本持平（1.04×）**——v3 的速度优势来自「NPU 检测被 GPU 双塔掩盖」，而不是绝对算力。
- **能力边界**：部署模型几乎不拒答（1/20），v1 能拒答（11/20）；这是 v3 架构的真实缺口。
- **唯一大空间**：GPU 双塔 89.4 ms（CUDA Graph 只能省 7%）；若补上 Triton/inductor 到 ~56 ms，端到端可到 **~174 ms**。
